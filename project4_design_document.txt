             ============================

---- DATA STRUCTURES ----

>> A1: Copy here the declaration of each new or changed `struct' or
>> `struct' member, global or static variable, `typedef', or
>> enumeration.  Identify the purpose of each in 25 words or less.

struct inode_disk
  {
    // block_sector_t start;               /* First data sector. */
    off_t length;                       /* File size in bytes. */
    unsigned magic;                     /* Magic number. */
    uint32_t direct[123];               /* Not used. */   // 125 - 1 - 1
    uint32_t indirect;               /* Not used. */
    uint32_t dindirect;               /* Not used. */
    uint32_t qwerty;
  };

we changed struct inode_disk.
we removed block_sector_t start. This will not be used, since we used indexed file.

uint32_t direct[123] is direct index.
uint32_t indirect is indirect index.
uint32_t dindirect is doubly indirect index.

uint32_t qwerty is padding. this make inode_disk be 512 byte.




>> A2: What is the maximum size of a file supported by your inode
>> structure?  Show your work.

direct block : 123 * 512 byte = 62976 byte.

indirect block : block can point 512 / 4 = 128 blocks.
                128 * 512 byte = 65536 byte.
doubly indirect block : each block can point 512 / 4 = 128 indirect block.
                        128 * 65536 byte =  8388608 byte.

in total : 62976 + 65536 + 8388608 = 8517120 byte.


---- SYNCHRONIZATION ----

>> A3: Explain how your code avoids a race if two processes attempt to
>> extend a file at the same time.

We have put filesys lock which is filesema in our implementation,
thus only one can try to change a file at a time.




>> A4: Suppose processes A and B both have file F open, both
>> positioned at end-of-file.  If A reads and B writes F at the same
>> time, A may read all, part, or none of what B writes.  However, A
>> may not read data other than what B writes, e.g. if B writes
>> nonzero data, A is not allowed to see all zeros.  Explain how your
>> code avoids this race.

When accessing the file system, locks are used to prevent race conditions.
This ensures that a process either:
reads the file after another process finishes writing to it, or
reads the file before any writing begins (in this case, the process reads nothing).




>> A5: Explain how your synchronization design provides "fairness".
>> File access is "fair" if readers cannot indefinitely block writers
>> or vice versa.  That is, many processes reading from a file cannot
>> prevent forever another process from writing the file, and many
>> processes writing to a file cannot prevent another process forever
>> from reading the file.

we used semaphore and did not implement sharing.
Thus, Since semaphore list is implemented as first-come-first-served, there is no concern of fairness.  


---- RATIONALE ----

>> A6: Is your inode structure a multilevel index?  If so, why did you
>> choose this particular combination of direct, indirect, and doubly
>> indirect blocks?  If not, why did you choose an alternative inode
>> structure, and what advantages and disadvantages does your
>> structure have, compared to a multilevel index?

our inode_disk struct uses a multilevel index.
we used 123 direct pointer, one indirect, and one doubly indirect.
direct pointer help inode to access block fast.
indirect and doubly indirect block make inode cover large file size.
