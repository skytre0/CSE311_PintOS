PAGE : 
page = virtual page
page size = 4096 byte, page-aligned
각 process independent user pages 존재 = PHYS_BASE 아래 = kernel page는 global하게 공유

FRAME : 
frame = physical frame (page frame)
frame도 page와 size, align 동일.
direct access 불가능 = physical memory를 kernel virtual memory와 mapping하는 것으로 해결
-> first page = first frame....으로 해결함 -> 관련 translate function 제공함.

PAGE TABLE : 
virtual address(page) -> physical address(frame) 으로 translate에 사용함.
-> offset은 그대로, page number만 frame number로 변환해서 접근.

SWAP SLOTS : 
continuous, page-size의 swap partition 내부 region -> page-align되어야 함.

-> 이 주석이 있긴 함.

page_fault() 구현 개요 : 
1. fault한 page locate -> reference가 valid하면 supplemental로 data locate (장소는 file system, swap slot, 그냥 0) -> sharing 구현 시 data가 page table이 아니라 frame에 존재 가능 -> invalid한 locate의 access 가능성 있음(종류 약 3개) -> terminate & free all resource
2. page 저장할 frame 얻기, sharing 구현 시 frame을 locate 가능해야 함
3. frame에 data 넣기 -> 가능한 장소들에서 read해서
4. fault의 경우 pte를 physical page로 point해라 -> userprog/pagedir.c 확인

frame table eviction : 
choose frame to evict -> accessed & dirty bit 유용할 것 -> 이 frame reference하는 page table의 ref remove(sharing 없으면 1 page ref) -> 필요하다면 page를 file sys에 write or swap해야 다른 page 저장 가능

accessed & dirty bit : read/write : access = 1, write : dirty = 1 -> CPU는 이 bit 0으로 안 하지만, OS는 함.
aliases : 다수 page가 same frame 접근 -> 현재 접근하는 page만 access, dirty bit 변경 = 다른 page는 변경 X -> 주의점은 모든  user virtual이 kernel virtual과 alias 됨 = 이거 handle 필요 (ex로 both address bit check, only access user data through user virtual address 등)
